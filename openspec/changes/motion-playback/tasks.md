# Tasks

## 1. Stock motion data

- [ ] 1.1 Write `tools/extract_motions.py`. It checks the SHA-256 of `baseline/original-flash-4MB.bin` against `baseline/README.md`, reads the 15 step counts at flash 0x4AE84 and the table rows, the centre pose (0x40DE8) and the zero pose (0x40E0C) at the offsets in design.md's evidence table, checks that angles are 0–180, that durations are positive and that the 15 tables tile flash 0x3FC9C–0x40DE7 without gaps or overlaps, and writes `core/motion/stock_motions.h`, marked generated. Verify: `mise exec -- python -I tools/extract_motions.py` writes the header; run against a copy of the image with one byte changed, it exits non-zero without writing.
- [ ] 1.2 Add the mise tasks `extract-motions` (regenerate) and `check-motions` (re-extract in memory, compare with the checked-in header, and name the motion and keyframe that differ). Verify: `mise run check-motions` exits 0 on a clean checkout, and exits non-zero naming the motion and keyframe after one angle in the header is edited by hand (revert the edit afterwards).
- [ ] 1.3 Write `docs/stock-motions.md`: for each `pm` 1–15, 99 and 100, the table address, step-count address, keyframe count and composition, citing `docs/lafvin-comparison.md` and `docs/lafvin-motions.md`, and the stock behaviours that the player deliberately does not reproduce (boot zero routine, endpoint shortfall, blocking playback). Verify: every row of design.md's evidence table appears in the document with its source, and the generated header's keyframe counts equal the document's.

## 2. Keyframe format and player in `core/`

- [ ] 2.1 Add `core/motion/keyframe.h` with the types in design D2 and the motion catalogue (ids 1–15, 99 and 100, names, one or two tables or a direct pose each) over the generated tables. Verify: a host test checks the catalogue's ids and names, and each table's keyframe count, first keyframe and last keyframe against the spec (Standby 2 … Dance 3 10, centre and zero pose 135, 45, 135, 45, 45, 135, 45, 135, standby pose 70, 90, 90, 110, 110, 90, 90, 70), and `mise run test` passes.
- [ ] 2.2 Implement the player in `core/motion/player.{h,cpp}`: `request`, `play_keyframe`, `keyframe_ended`, `stop`, `service(now_ms)` with the deadline scheduling of design D4, the exact-endpoint interpolation (D3), the direct-pose routine, the start pose taken from servo output's commanded angles (D6), the enable request at the first tick of a motion started while idle, the mode check before every other tick and refused-enable and refused-write handling (D11), the pending slot (D5) and the state report, over the servo-output interface of D4. Verify: `mise run test` and `mise run build` compile it without any change to the build's source selection (firmware-build compiles every `core/` source).
- [ ] 2.3 Add host tests in the native env, one per spec scenario, with a recording servo-output model (commanded angles, a mode, a token that goes stale on the safe state, refusal of an enable request or a write on demand) and a simulated clock. They cover the catalogue, Centre and rejected ids (0, 16, 98, 101), the composites, the first and last tick (133 at tick 1, 90 at tick 20), the 375 ms keyframe (37 ticks, `floor(n/2)` 18), durations of 0 and 9 ms, Standby from zero ending exactly at the standby pose, unchanged servos, the start pose after a direct servo command, on-time ticks, the slightly late tick (19 ms, then 20 ms), the stall (60 ms, then 70 ms), the late chance at the end of a motion, consecutive motions (second Forward at 1650 ms), the direct-pose routine's 38 ticks and its end at 380 ms, no write in 10 s without a command, the first command after reset (complete zero pose, then 40 Standby ticks), the safe state during a motion, a refused write, a request after the safe state, a refused enable request, output enabled by another caller while idle (enable with the commanded angles, no movement, unchanged tick count), the single keyframe (while idle, during a motion, ended, pending not ended, stopped, zero duration, invalid), latest request wins, the same motion repeated, played once, stop, stop before a request starts, start pose after a stop, no clamping of 170 and the state report (including a request pending before its first tick, and before the first command). Verify: `mise run test` passes, and each test fails when the behaviour it covers is broken on purpose (check this once per test while writing it).
- [ ] 2.4 Add a trace test: a reference model of the stock loop, written straight from the disassembly cited in `docs/stock-motions.md` independently of the player, produces each motion's per-keyframe tick counts and keyframe angle sequence for motions 1–15, 99 and 100, from the zero pose and from the standby pose. The test requires the player's trace to have the same tick count per keyframe, to write each keyframe's angles exactly at its last tick for every servo that changes, to leave servo output's commanded angles equal to the keyframe angles at each keyframe end, and its tick totals to equal design.md's duration table. Verify: `mise run test` passes, and the test fails when the player is changed to stock's endpoint shortfall.

## 4. Demonstration build

- [ ] 4.1 Add the `motion-demo` PlatformIO env and the `-DMOTION_DEMO` sequence of design D9 (wait for `go` on the serial console; motions 1–15, 99 and 100 with 2 s pauses; stop Forward after 500 ms; request motion 1 1 s into Dance 1; one 500 ms keyframe), logging the lines of D9. Verify: `mise exec -- pio run -d firmware -e motion-demo` builds, and `nm` on the normal env's ELF finds no demo symbol.
- [ ] 4.2 Write `tools/check_motion_log.py`. It reads a captured log and requires the demo sequence in order: `complete` runs of motions 1–15, 99 and 100, then an `interrupted` Forward whose `command stop` is 500 ± 10 ms after its start, then a `complete` Dance 1 whose `command request 1` is 1000 ± 10 ms after its start, then a `complete` Standby of 40 ticks whose start equals Dance 1's end within 10 ms, then a keyframe of 50 ticks. It checks each `complete` run's tick count against the generated tables (plus one enable tick for the first motion) and its duration within 5% of design.md's figures. For the `interrupted` Forward it checks that `last_write` is not later than the stop's time and that it has fewer than 165 ticks. (That no angle is written after a stop is proven by the host tests, task 2.3.) Verify: it passes on a log produced by the host player on a simulated clock and fails on a log with one motion's ticks altered, on a log with one motion missing, and on a log with the stop command 600 ms after Forward's start.

Verify: both results are referenced in `docs/stock-motions.md`; if either is missing or failed, stop here.
- [ ] 5.2 Upload the `motion-demo` build with the robot lifted so that no leg touches the ground, and reset it. Verify: for 10 s after the reset, before `go` is sent, no servo moves and the console shows no `motion` line.
- [ ] 5.3 With the legs still off the ground, send `go`, capture the log with `mise run monitor` and run `tools/check_motion_log.py` on it. Watch each servo's direction in the first Standby against the index-to-joint record of task 5.1. Verify: the script passes, the logged maximum tick time is under 2 ms (task 3.2), each servo moves in the recorded direction, and Sleep's 30°/150° and Say Hi's 170° poses are reached without a servo stalling at an end stop (or the safe-range clamp is recorded).
- [ ] 5.4 Record a video of each motion 1–15, 99 and 100 on the stock firmware (`mise run restore`, motions triggered from the stock controller and zero-check pages, 99 by `GET /controller?pm=99`) and on the `motion-demo` build, from the same start pose and camera position, first with the legs off the ground and then standing. Verify: for each motion, the same sequence of poses and a total duration within 10% of stock, recorded per motion in `docs/stock-motions.md`.
- [ ] 5.5 Upload the normal build again after the checks. Verify: `mise run check-motions` and `mise run test` pass, and after a reset the robot stays still until its first command.
