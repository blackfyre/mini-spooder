# Tasks

## 1. Stock motion data

- [ ] 1.1 Write `tools/extract_motions.py`. It checks the SHA-256 of `baseline/original-flash-4MB.bin` against `baseline/README.md`, reads the 15 step counts at flash 0x4AE84 and the table rows and zero pose at the offsets in design.md's evidence table, checks that angles are 0–180, that durations are positive and that the 15 tables tile flash 0x3FC9C–0x40DE7 without gaps or overlaps, followed by the `pm` 99 pose row at 0x40DE8 and the zero pose at 0x40E0C, and writes `core/motion/stock_motions.h`, marked generated. Verify: `mise exec -- python -I tools/extract_motions.py` writes the header; run against a copy of the image with one byte changed, it exits non-zero without writing.
- [ ] 1.2 Add the mise tasks `extract-motions` (regenerate) and `check-motions` (re-extract in memory, compare with the checked-in header, and name the motion and keyframe that differ). Verify: `mise run check-motions` exits 0 on a clean checkout, and exits non-zero naming the motion and keyframe after one angle in the header is edited by hand (revert the edit afterwards).
- [ ] 1.3 Confirm the extraction from the stock disassembly. Disassemble the irom segment that `tools/extract_motions.py` cuts from the baseline image (not the copy in `references/`), using the PlatformIO Xtensa `objdump`. For each `pm` 1–15, confirm the table address and step-count address in the dispatch, the composites for `pm` 9 and 12, the zero routine and its 300 ms pause, the 10 ms base interval, the rounding of `map`, and whether the direct servo write path (`servo`/`value`) updates the interpolation start pose. Record each address in `docs/stock-motions.md`. Verify: every row of design.md's evidence table is marked confirmed in `docs/stock-motions.md`, or the spec and design are amended where a finding differs.
- [ ] 1.4 Record in `docs/stock-motions.md` how the stock tables differ from `references/lafvin/extracted/0.SpiderBot/actionarray.h`, read as data only. Verify: the document lists, for each motion, whether its keyframes match the vendor's, and the differences where they do not.

- [ ] 2.2 Implement the player in `core/motion/player.{h,cpp}`: `request`, `stop`, `return_to_standby`, `service(now_ms)` with the tick scheduling of design D4, the stock interpolation (D3), the zero routine, the start-up zero, the pending slot (D5), the start pose after an abort (D6), and the state report. Verify: `mise run test` builds it in the native env with the source filter updated.
- [ ] 2.3 Add host tests in the native env, one per spec scenario, with a recording servo sink and a simulated clock. They cover the catalogue and rejected ids (0, 16, 99, 101), the composites, the first and last tick (135 at tick 0, 92 at tick 19), the 375 ms keyframe (37 ticks, half-period 187), Standby from zero ending at 71 and 88, unchanged servos, on-time and late ticks, the zero routine's 38 ticks and its end at 380 ms, consecutive motions (second Forward at 1650 ms), stop and return to standby during the start-up routine, start-up, latest request wins, the same motion repeated, idle after the last motion, stop, stop before a request starts, start pose after a stop, a slightly late tick (19 ms, then 29 ms), return to standby, a request for motion 1 during a motion, no clamping of 170 and the state report. - [ ] 2.4 Add a golden-trace test: a reference model of the stock loop, written straight from the disassembly in `docs/stock-motions.md` independently of the player, produces the `(tick, servo, angle)` trace of every motion 1–15 and 100 from the zero pose and from the standby pose. ## 4. Demonstration build

- [ ] 4.1 Add the `motion-demo` PlatformIO env and the `-DMOTION_DEMO` sequence of design D9 (motions 1–15 and 100 with 2 s pauses, then stop Forward after 500 ms, then return to standby 1 s into Dance 1), logging `motion <id> start <ms> last_write <ms> end <ms> ticks <n> <complete|interrupted>` for each motion and `command <stop|standby> <ms>` for each interruption at 115200 baud. Verify: `mise exec -- pio run -d firmware -e motion-demo` builds, and `nm` on the normal env's ELF finds no demo symbol.
- [ ] 4.2 Write `tools/check_motion_log.py`. It reads a captured log and requires the demo sequence in order: `complete` runs of motions 1–15 and 100, then an `interrupted` Forward whose `command stop` is 500 ± 10 ms after its start, then an `interrupted` Dance 1 whose `command standby` is 1000 ± 10 ms after its start, then a `complete` Standby. It checks each `complete` run's tick count against the generated tables and its duration within 5% of design.md's figures. For the two `interrupted` runs it checks instead that the stopped Forward's `last_write` is not later than its `command stop` time and its tick count is below 165, and that the interrupted Dance 1's `last_write` is not later than its `command standby` time and is followed by a `complete` Standby of 40 ticks. (That no angle is written after a stop is proven by the host tests with the recording sink, task 2.3.) Verify: it passes on a log generated by the host reference model and fails on a log with one motion's ticks altered, on a log with one motion missing, and on a log with the stop command 600 ms after Forward's start.
