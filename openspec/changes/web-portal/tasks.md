# Tasks

Hardware tasks (group 6) need the user's go-ahead before anything is written to the robot. Every esptool command resets the board. Groups 1–5 need no hardware.

## 1. Tokens, labels and page generator

- [ ] 1.1 Copy the design system's `project/tokens.json` (artifact JX4X2WDSVT48H94TboBR6V, version `1794044556-c45e`) to `firmware/portal/tokens/tokens.json`, and write `firmware/portal/tokens/SOURCE.md` with the artifact URL, version and SHA-256. Verify with `sha256sum firmware/portal/tokens/tokens.json`, which must equal `25da75f563fb81140601fa92a83dde5ec8449bfdc84a38e2608f50016e35fb73` or the newer hash recorded in `SOURCE.md`.
- [ ] 1.2 Write `firmware/portal/servo_labels.json`: the GPIO for servo indices 0–7 (15, 13, 12, 14, 2, 4, 5, 16, from servo-output). Write `tools/portal/gen_pages.py`. It reads `firmware/portal/pages/*.html` and the shared fragments, emits a `:root` block with the Paper (`light`) value of every `bf-*` token that the pages use, fills the `S<i> · GPIO<g>` labels from `servo_labels.json`, inlines the fragments, and writes `portal_pages.h` (one `PROGMEM` string per page) to the build directory. Verify: two runs produce byte-identical output (`cmp`), and a page that uses an unknown `var(--bf-x)` makes the generator exit non-zero.
- [ ] 1.3 Write `tools/portal/check_pages.py`. It checks the token values, that every `var(--bf-*)` used is defined, that there are no external references (`http:`, `https:`, `//`, `@import`, `src=` or `href=` to a file), the viewport meta on every page, the 16 KB per-page budget, the stock control table (decision 2 in design.md: `pm`, `servo` and `value` per control, defaults, slider directions and arrangement by servo index), that no page sends `pms` or `/online`, and that `servo_labels.json` equals servo-output's index-to-GPIO table in the firmware source. Verify: it passes on the generated pages, and it fails on each of four fixtures under `tools/portal/fixtures/`: a wrong token value, an external stylesheet link, a wrong `data-value`, and a label table with GPIO14 for servo 0.
- [ ] 1.4 Add the mise tasks `portal-gen` (runs the generator) and `portal-check` (runs the generator, then the check), and a PlatformIO `pre:` extra script in `firmware/` that runs the generator before every build. Verify: `mise run portal-check` passes, and after `touch firmware/portal/pages/controller.html`, `mise run build` regenerates `portal_pages.h`, as its timestamp shows.

## 2. Core request handler (host-tested)

- [ ] 2.1 Add the portal handler to `core/`: the request type (method, path, arguments), the read-only context (safe state set, motion busy, valid motion ids, angle range, trim range) and the result type (status, content type, body, at most one action), with strict integer parsing (optional sign and digits only, within 32-bit range). Verify: the native environment builds, and a Unity test of the integer parser passes for `"7"`, `"-5"` and `"+3"`, and fails for `""`, `"7a"`, `"1.5"`, `" 7"` and `"99999999999"`.
- [ ] 2.2 Implement `/controller`: `pm` (a valid id, including 99 and 100, gives 200 `(pm)=(<pm as received>)` and a motion request, tested with `pm=02` giving `(pm)=(02)`; an integer that is not an id, such as 21, 0 or -1, gives the same 200 echo and no action; an empty or non-integer `pm` gives 400), `servo` with `value` (stop plus move, body `(pm)=()`; a missing or invalid index or value gives 400), `pm` together with `servo` (400), and `pms` only (200 `(pm)=()`, no action). Verify with Unity tests covering every scenario of "Motion request", "Direct servo command" and "Unused pms parameter" in the spec; `mise run test` passes.
- [ ] 2.3 Implement `/save`: keys 0–7 with a value in range store the trim, with body `(key, value)=(<i>,<v>)`; key 100 resets all, ignoring a missing or malformed value, with body `(key, value)=(100,0)`; any other key, or a missing or invalid value, gives 400 and no action; with motion busy, a save gives 409 `text/plain` and no action; with the safe state set, a save is still accepted. Verify with Unity tests covering the "Calibration save" scenarios that need no hardware and both boundaries of the trim range from the context; `mise run test` passes.
- [ ] 2.4 Implement `/online`: nine required parameters, angle and `t1` (0–60000) ranges, a keyframe action, and body `(m0, m1)=(<a0>,<a1>)` returned with the action (no wait). Verify with Unity tests for a valid request, a missing `m5`, `t1=0`, `t1=60000`, `t1=60001` and `t1=-1`; `mise run test` passes.
- [ ] 2.5 Implement the safe state and fall-through: with the safe state set, `pm`, `servo` and `/online` give 503 `text/plain` and no action, checked before parameter validation (so `servo=3` without `value` gives 503), while `pms`-only, `/save` and page paths are unaffected; with a remote's session live and no safe state, the same requests are accepted (the context has no "remote connected" input). Unknown paths and non-GET methods give 404 `text/plain` `Not found: <path>`. Verify with Unity tests for each "Safe state refuses movement", "Shared control with the remote" and "Portal server and address" scenario that needs no hardware; `mise run test` passes.

## 3. Pages

- [ ] 3.1 Write the shared fragments: the stylesheet (Paper tokens, mono uppercase labels, 44 px buttons, focus ring, 320 px layout, the two servo-group tones), the navigation bar marking the current page, the status line, and one click handler. The handler sends a control's `data-*` request with a 5 s timeout and reports 200, 400, 409, 503, or no answer (saying that the command may still have run). Verify: `mise run portal-check` passes.
- [ ] 3.2 Write `controller.html`: the title `Spider Robot.`, fifteen motion buttons in the stock order and grouping, no button for 99 or 100, and no vendor title or shop advert. Verify: the stock control table in `portal-check` passes for `/`.
- [ ] 3.3 Write `zero.html`: eight servo buttons in the stock arrangement by index with `S<i> · GPIO<g>` labels and their zero-check angles, and Zero position sending `pm=100`. Verify: `portal-check` passes for `/zero`.
- [ ] 3.4 Write `setting.html`: eight trim fields with placeholders `{{OFF0}}`…`{{OFF7}}`, SET buttons sending `/save?key=<i>&value=<field>`, and RESET ALL that zeroes the fields and sends `/save?key=100&value=0`. Verify: `portal-check` passes for `/setting` and confirms all eight placeholders are present.
- [ ] 3.5 Write `editor.html`: sliders 45–135 with the stock defaults and directions, fields, Send buttons, slider release sending `servo` and `value`, the Action Code line, and Standby. Verify: `portal-check` passes for `/editor`. Open the generated page in a desktop browser with the request URL logged instead of sent: moving the `S6` slider to 120 shows `70, 90, 90, 110, 110, 90, 120, 70`.

## 4. Firmware integration

- [ ] 4.1 Add the portal module to `firmware/`: `ESP8266WebServer` on port 80, the seven routes and `onNotFound` passed to the core handler, and the actions carried out through motion-playback, servo-output and servo-calibration. Static pages are sent with `send_P`, and `/setting` is sent in chunks with the trims filled in. Verify: `mise run build` succeeds, and its memory report shows the portal adds no page-sized static RAM buffer (the pages sit in flash).
- [ ] 4.2 Register the portal's `handleClient()` as the HTTP step of firmware-foundation's main loop, and fill the handler context from servo-output (safe state) and motion-playback (busy, ids) on every request. No handler loops, delays or calls a service step. Verify: `mise run build` succeeds, `mise run test` passes, and `grep -rn 'delay(' firmware/portal/` finds nothing.

## 6. Hardware verification (user's go-ahead required)

Run these in order. Run 6.3 and 6.4 with the robot's legs off the ground, before any walking motion.

- [ ] 6.1 With the user's go-ahead, flash with `mise run upload`. Join the robot's access point from a phone and open `http://<robot address>/` within 10 s of power-on. Verify: the Controller page loads, the phone browser's network log shows only the page request, and no servo moved on boot or on loading the page.
- [ ] 6.2 From a laptop on the access point, run `curl -i 'http://<robot address>/controller?servo=3'`, `curl -i 'http://<robot address>/controller?pm=21'` and `curl -i 'http://<robot address>/generate_204'`. Verify: the first answers 400, the second 200 `(pm)=(21)`, the third 404 `Not found: /generate_204`, and nothing moves.
- [ ] 6.3 Legs off the ground: on `/zero`, tap each servo button, then Zero position. Verify: each button moves only the servo on its labelled GPIO to the zero-check angle, and note the joint and direction it moves for comparison with firmware-foundation's joint map; Zero position moves all eight.
- [ ] 6.4 Legs off the ground: on `/editor`, move each slider and use one Send. Verify: the right servo follows in the slider's direction, and the Action Code line matches the fields. Then run `curl -i 'http://<robot address>/online?m0=70&m1=90&m2=90&m3=110&m4=110&m5=90&m6=90&m7=70&t1=1000'`. Verify: it answers 200 `(m0, m1)=(70,90)` within 1 s, before the move ends, and the robot reaches that pose after about 1 s.
- [ ] 6.5 On the ground, tap each of the fifteen Controller buttons. Verify: each plays its motion, and while Push up plays, opening `/zero` returns within 1 s.
- [ ] 6.6 With servo 1 held at 90° from the editor and no motion playing, SET a trim of -5 for `S1`. Verify: only servo 1 moves, by the trim change. Tap Forward and SET a trim while it plays: the status line reports that a motion is playing, and the trim is unchanged. Power-cycle and reopen `/setting`: the saved trim is shown. Then RESET ALL and power-cycle: all fields show `0`.
- [ ] 6.7 When drive-link and the pak (or drive-link's test client) are available, start a session with Standby as its last request, then tap Dance 1 on the portal. Verify: Dance 1 plays (the remote's unchanged frames do not undo it). Then stop the remote's frames past drive-link's link-loss timeout while a servo is held from `/zero`. Verify: servo output enters the safe state, tapping a Zero check button reports the safe state (503) and nothing moves, and `/setting` still loads.
- [ ] 6.8 Open each page in a phone browser at 320 CSS px width (or desktop responsive mode). Verify: there is no horizontal scrolling, buttons are at least 44 px tall, and the keyboard focus ring is visible.
